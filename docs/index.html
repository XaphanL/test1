01
ФУНДАМЕНТ

База языка

xПеременные и типыОбъявление, нулевые значения, размеры 
var n int     // 0
name := "Go"  // только внутри функции
const max = 100
  • Переменная — имя для значения определённого типа.
  • Числа, bool, массивы и структуры передаются копированием.
  • int — 32/64 бита; byte = uint8; rune = int32.
  • UTF-8: латиница обычно 1 байт, кириллица обычно 2, кодовая точка — 1–4 байта.

Собес: Go статически типизирован, у переменной есть тип и нулевое значение.

ƒФункции и deferСигнатура и порядок выполнения 
func divide(a, b float64) (float64, error)
defer resource.Close() // вызов при выходе, LIFO
  • Функции — значения: их можно передавать и возвращать.
  • defer выполняется при return и раскрутке panic в обратном порядке.
  • Go передаёт всё по значению; копия иногда содержит ссылку на общие данные.
{}ЗамыканияФункция помнит окружение 
func counter() func() int {
    n := 0
    return func() int { n++; return n }
}

Замыкание — функция вместе с захваченными переменными внешней области. Они живут, пока доступны замыканию.

С Go 1.22 переменные, объявленные в заголовке for, создаются для каждой итерации. Явная передача i аргументом всё равно остаётся ясной.

02
МОДЕЛЬ ДАННЫХ

Коллекции и структуры

[N]МассивФиксированный размер, значение целиком 
a := [3]int{10, 20, 30}
b := a // все элементы скопированы
  • Длина входит в тип: [3]int и [4]int — разные типы.
  • Передача в функцию копирует массив; указатель *[N]T позволяет менять оригинал.
[]СлайсОкно над массивом: ptr + len + cap 
s := make([]int, 2, 4)
s = append(s, 30)
  • Копия дескриптора обычно видит тот же backing array.
  • append может выделить новый массив — результат всегда присваивают.
  • Независимая копия: clone := append([]T(nil), s...).
K→VMapКлюч → значение, хеш-таблица 
m := make(map[string]int)
m["go"] = 1
v, ok := m["go"]
delete(m, "go")
  • Ключ должен быть сравнимым; slice и map ключами быть не могут.
  • Из nil map читать можно, записывать — panic: хранилище не создано.
  • Копии map обращаются к одной runtime-таблице. Конкурентные записи требуют синхронизации.
SСтруктуры и композицияПоля, методы, вложение и встраивание 
type Service struct { repo Repository } // вложение
type Admin struct { User }               // встраивание
  • Вложенное поле: s.repo.Save().
  • У встроенного типа методы продвигаются: admin.Rename().
  • Встраивание — композиция, а не наследование.
＋make и newИнициализация против выделения значения 
p := new(int)             // *int → 0
s := make([]int, 0, 10)  // готовый slice
m := make(map[string]int) // готовая map
ch := make(chan int, 5)   // готовый channel

new(T) возвращает указатель на нулевое T. make применяется только к slice, map и channel и создаёт их внутреннюю структуру.

03
GO-WAY

Интерфейсы и дизайн

IИнтерфейсыПоведение вместо данных 
type Writer interface {
    Write([]byte) (int, error)
}
  • Тип реализует интерфейс неявно, если имеет нужный набор методов.
  • Принимай интерфейс там, где нужна подмена; возвращай конкретный тип.
  • Интерфейс с typed nil внутри уже не равен nil.
T?Type assertion и type switchДинамический тип интерфейса 
s, ok := v.(string)
switch x := v.(type) {
case string: fmt.Println(len(x))
case int:    fmt.Println(x * 2)
}

Assertion проверяет один тип; type switch выбирает из нескольких. Assertion без ok паникует при несовпадении.

◇ООП в GoБез классов и наследования
  • Инкапсуляция: экспорт определяется регистром первой буквы.
  • Абстракция: интерфейсы описывают требуемое поведение.
  • Полиморфизм: разные типы реализуют один интерфейс.
  • Композиция: структуры содержат или встраивают типы.
APIAPIКонтракт взаимодействия

API — правила взаимодействия компонентов. В Go это экспортируемые сущности пакета, интерфейс или сетевой HTTP/gRPC-контракт.

GET /users/42 → 200 {"id":42}
POST /users   → 201 Created

Хороший API стабилен, валидирует вход и скрывает детали реализации.

04
КОНТРОЛЬ ОТКАЗОВ

Ошибки, panic и recover

!Ошибка как значениеСоздание и возврат 
var ErrNotFound = errors.New("not found")
if err != nil {
    return fmt.Errorf("load user %d: %w", id, err)
}

error — интерфейс с методом Error() string. Ожидаемые сбои возвращаются значением.

⛓%w, errors.Is и errors.AsЦепочка причин 
errors.Is(err, ErrNotFound) // конкретная причина
var pe *os.PathError
errors.As(err, &pe)         // ошибка нужного типа
  • %w добавляет контекст, сохраняя причину.
  • Is ищет значение/категорию; As — тип.
  • errors.Join объединяет несколько причин.
⚡panic, defer, recoverАварийный путь 
defer func() {
    if v := recover(); v != nil { log.Println(v) }
}()
  • Panic раскручивает стек и выполняет defer.
  • Recover работает только в отложенной функции той же горутины.
  • Для штатных ошибок используй error; recover обычно ставят на границе системы.
05
ОДНОВРЕМЕННАЯ РАБОТА

Горутины и каналы

goГорутиныКонкурентный запуск функций 
var wg sync.WaitGroup
wg.Add(1)
go func() { defer wg.Done(); work() }()
wg.Wait()

Горутина — лёгкая задача runtime. WaitGroup ждёт завершения группы, но не защищает данные и не передаёт ошибки.

→КаналыСинхронизация и передача значений 
ch := make(chan int, 2)
ch <- 42
v, ok := <-ch
close(ch)
  • Небуферизованный канал синхронизирует пару; буфер разъединяет её до заполнения.
  • Закрывает обычно отправитель. Отправка после close — panic.
  • Закрытый пустой канал возвращает zero value и ok=false.
⇄selectОжидание нескольких операций 
select {
case v := <-data: use(v)
case <-ctx.Done(): return ctx.Err()
case <-time.After(time.Second): return ErrTimeout
}

Select ждёт готовую операцию. При нескольких готовых выбирает одну псевдослучайно; default делает проверку неблокирующей.

🔒СинхронизацияОбщая память без гонок
  • Mutex — один владелец; RWMutex — читатели или один писатель.
  • WaitGroup — ожидание; Once — однократный запуск.
  • Cond — ожидание условия; atomic — атомарное простое состояние.

Проверка: go test -race ./....

⤨Конкурентные паттерныWorker pool, semaphore, pipeline
  • Worker pool: N воркеров читают общую очередь.
  • Semaphore: лимит одновременно выполняемых операций.
  • Bounded queue: лимит ожидания и backpressure/отказ.
  • Fan-out: один поток → несколько обработчиков.
  • Fan-in: несколько потоков → один канал.
  • Pipeline: выход этапа → вход следующего.

Главное: продумать отмену, ошибки, закрытие каналов и завершение горутин.

06
ПОД КАПОТОМ

Runtime и планировщик

GMPМодель G–M–PКак запускаются горутины
  • G: goroutine — функция, стек, состояние.
  • M: machine — поток ОС.
  • P: processor — ресурс runtime и локальная очередь G.

M исполняет G, владея P. GOMAXPROCS задаёт число P. Планировщик использует локальные/глобальную очереди, work stealing, netpoller и вытеснение.

MEMСтек, куча и GCГде живут значения

Escape analysis решает размещение значения. Стек горутины растёт; значения с более долгим или общим временем жизни могут уйти в кучу. GC освобождает недостижимые объекты.

Указатель не означает автоматическую кучу — решение принимает компилятор.

≡ДескрипторМалое описание больших данных

Это не ключевое слово Go, а термин для небольшого значения, описывающего runtime-данные.

  • Slice: указатель + len + cap.
  • String: указатель + длина.
  • Interface: динамический тип + значение.
  • Map/channel ссылаются на runtime-структуры.

Копирование дескриптора не обязательно копирует данные за ним.

ПРОДАКШЕН

Контекст и архитектура

ctxcontext.ContextОтмена, дедлайн, данные запроса 
func Load(ctx context.Context, id int) error
ctx, cancel := context.WithTimeout(parent, 2*time.Second)
defer cancel()
  • Передаётся первым параметром, не является глобальной переменной.
  • Отмена родителя отменяет потомков; обратно — нет.
  • Горутина сама слушает ctx.Done(): отмена кооперативная.
  • Value — для метаданных запроса, не бизнес-параметров.
↓Graceful shutdownЗавершение без потери работы
  1. Поймать SIGINT/SIGTERM через signal.NotifyContext.
  2. Прекратить приём новых запросов.
  3. Отменить фоновые задачи.
  4. Дождаться активных работ с тайм-аутом.
  5. Закрыть ресурсы.

У shutdown должен быть конечный дедлайн.

1×ИдемпотентностьПовтор не меняет конечный эффект

Повтор операции с теми же входными данными даёт тот же конечный эффект, что один вызов.

  • Для повторяемого POST используй idempotency key.
  • Сохраняй ключ и результат атомарно с операцией.
  • Учитывай конкурентные дубликаты и срок жизни ключа.
▤Слои и зависимостиГраницы важнее папок 
HTTP handler → Service → Repository → DB
                 ↑
          бизнес-правила
  • Handler адаптирует транспорт; service ведёт сценарий; repository скрывает хранение.
  • Зависимости передаются явно, интерфейс обычно объявляет потребитель.
  • Алгоритм — шаги решения; реализация — конкретный код и технологии.
